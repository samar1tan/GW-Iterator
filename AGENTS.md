# GW-Iterator working agreements

- Build the local iteration supervisor described in `docs/PRD.md` and `docs/UED.md`. GitWorld and GW-Iterator are separate local project configurations using one engine. Preserve the user-requested scope; do not turn the first version into a visual-only workflow demo.
- Conversations and private working notes are Chinese. Public documentation, issues, commits and code comments are English. Keep UI copy separate from execution state and support English and Simplified Chinese.
- Use the GitWorld v0.1 retrospective to guide bounded runs, explicit outcomes, cross-boundary regression, artifact maintenance and useful human supervision. Run focused checks and lightweight replays, not GitWorld's full acceptance matrix or another product-polish cycle.
- Write/update the relevant PRD before substantive module behavior. Keep interaction, implementation and API documentation aligned; a PRD is not completion evidence.
- Project, pipeline and role configurations, workspace paths, knowledge contents, agent memory, run transcripts, access tokens, credentials, screenshots and local audit exports are private. Store them under ignored `.local/` or another explicit local data directory. Do not commit real configuration files, personal assets or private material disguised as fixtures. Public types, schemas, build manifests and independently authored synthetic tests are implementation source.
- Bind the server to loopback. Validate requests, scope agent control tools to their project, preserve sandbox/approval decisions and never silently weaken security to complete a step. Use the installed Codex authentication without reading or copying credential files.
- Pin project, role, pipeline and knowledge revisions in each run. Configuration edits affect new runs; review/retry records preserve the earlier attempts. Never invent success, token usage, fees, live handles or CI completion.
- Manual triggers and authorized autonomous loops share the same scheduler. Deduplicate starts, bound retries/concurrency/time, show blockers and stop on completion or an explicit limit. Human feedback is a normal input, not a reason to discard run history.
- Give the project list, project pipelines, role knowledge and project settings stable spatial meaning. Inspect the implemented UI and exercise the affected journey; avoid decorative placeholders and redundant controls.
- Assign an owner and independent reviewer to substantial implementation and publication. Reuse focused role agents when useful; provide narrow context and explicit file ownership instead of duplicating the entire investigation. Record actual findings and their resolution.
- Use GitHub Issues/PRs/CI for public work. Stage exact reviewed paths, inspect source/history and dependency notices, and scan the publication candidate for private paths/configuration/secrets before push. Keep local review records private. Attach every created PR to the task.
- Existing Apache-2.0 covers original contributions. Multica and Google are design references; do not copy their source, assets or prose into the app. Preserve third-party dependency licenses.
