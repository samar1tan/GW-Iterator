# Resolve interrupted and waiting work

## User outcome

A person sees what blocks work and can continue from that location. They do not have to refresh an external status, interpret a technical recovery recommendation, find another page and then retry. Routine account-reading expiry is background observation, not a demand for attention.

## Behavior

- An explicit owner Stop or refusal ends the current request for attention. Stopped/completed goals and cancelled/completed executions belong to results/history, even when an earlier recovery record still says checking or needs input. Historical recovery, failure and external-cleanup evidence remains inspectable; it cannot create a current retry decision, active-work count or pending-work badge. Only a fresh owner continuation can make that work current again.
- Apply the same current-state precedence to global and project workbenches, selected goal/execution details, summary projections and acknowledged-receipt overlays. A later Stop or terminal observation supersedes an older recovery receipt. Old records do not require a private-data migration to render correctly. Genuine failed work, human/review/account waits and newly authorized recovery retain their actions.
- For a failed or held stage, show one primary Retry step / Continue step action beside the actual state, with an optional note in the ordinary surface. The note reaches the next attempt as feedback. A requested continuation checks current state and reconciles the exact external task automatically before retrying; it never repeats already accepted stages.
- Reconciliation has a finite deadline and never starts another execution while external termination is unconfirmed. If it cannot establish safety, retain the result and expose a concrete external-inspection/Check again action. Do not silently extend attempts, time, tokens, permissions or model scope.
- A genuine account uncertainty/near-limit decision or execution-bound extension shows its actual evidence and the corresponding explicit one-step action. Known exhaustion offers refresh and the real reset time. A healthy updated account reading does not require approval, and missing comparison samples do not require quota configuration.
- Paid dispatch uses one freshly assessed observation under the admission lock and records that same service-issued basis. A second unconditional read must not create a false changed-reading hold. Preserve exact owner permits, authoritative exhaustion and fresh Stop/attempt checks.
- A continuation returns either a durable accepted run receipt or an explicit current decision without starting work. Refresh failure never converts a successful continuation into failure or resubmits it. A slow/failed decision read offers a retry-read and retains existing actions; it cannot spin indefinitely.
- Use the same actions from project/global goal inspection and pipeline stage inspection. Manual result/review waits keep their existing result and accept/revise controls; dependencies link to the named work; pause offers Resume/Stop. Do not display a text field where the executor cannot consume it.
- Quietly refresh account observations before they expire and again at submission. Routine expiry does not change a healthy summary into a warning or force a manual refresh. Failed refresh is shown at the point it actually prevents work, with details available on demand. Never claim an old reading is freshly confirmed.

## Acceptance

Cover changing healthy readings, caution/exhaustion/unknown data, forged or stale approvals, Stop during admission, single-click exact-scope reconciliation and continuation, retained accepted output, finite unknown cleanup, changed decision/limits, duplicate clicks, and successful continuation followed by failed observation. Add stopped/completed goals with every historical recovery phase, cancelled child runs with old manual/review/account gates, stale continuation receipts after Stop, and a fresh explicitly resumed recovery. Inspect global/project workbench counts, result badges and selected details in both locales. No model calls are needed for these state tests.
