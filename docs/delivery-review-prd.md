# Delivery review from actual evidence

## User outcome

A person can inspect a concrete prepared result and make a decision. GWI must not substitute an empty result-writing form for delivery review, nor depend on a separate coding assistant to assemble the evidence every time.

## Evidence before a decision

- Project and global execution inspection share a model-free review bundle beside manual/review decisions. It identifies the requested outcome, exact upstream attempts, reported findings and artifacts, actual prepared source changes (including eligible new files and deletions), retained browser screenshots, and separately identified publication evidence. Agent reports remain reports; missing or unavailable observations remain unknown. A connection or completed agent task is not proof of acceptance, CI or publication.
- Preview source and retained images through authenticated, project-scoped endpoints. Never accept a host path from the client for screenshot access, load remote media automatically, or expose credentials/runtime configuration. A missing preview, source observation or check is visible and recoverable rather than an empty successful result.
- New default change workflows include a bounded agent stage to organize delivery evidence before their separate owner gate. It preserves the actual candidate and independent QA; it does not implement again, run QA again, publish automatically or accept for the owner. Existing frozen definitions are unchanged.

## Supplementing insufficient material

- A waiting manual gate offers Prepare review material with an optional specific instruction. This creates or reuses one linked support execution through the ordinary scheduler and account checks. Refreshing or waiting never starts model work. Identical requests reuse the same durable execution, including after restart; changed guidance or input can justify a new request, without execution quotas.
- The support execution pins its parent run, stage, manual attempt, control revision, upstream output and prepared source manifest before its first dispatch. It reviews an independent copy of the parent's actual prepared checkout; an unavailable original checkout is a prerequisite failure, never a fallback to current project HEAD. The original run, accepted stages and files remain unchanged.
- Use the assigned frozen role's model, guidance and identity with reduced tools and bindings for evidence preparation. Retain source write protection and actual integrity checks; do not claim filesystem read isolation or network isolation that the runtime does not provide. Do not inherit unrelated skill/MCP write capabilities for this preparation task.
- Completing support only produces inspectable material. It never completes, approves or reworks its parent. Stop, a changed parent attempt, revision or decision invalidates pending support; late output remains history. Source changes make older material stale.

## Human decisions

- Present Accept delivery and Request changes next to the material. Acceptance uses the recorded artifacts and identifies the person's decision without inventing passed checks. Request changes requires a concrete finding and uses the workflow's configured rework target. Supplementing material does not requeue implementation or QA.
- Decisions carry an idempotency key and the observed bundle/attempt/control identity. Revalidate prepared source and current state, commit the receipt before dispatch and retain it across stale/failed refreshes. A stale bundle requires a fresh observation; Stop always wins.
- An `ownerGate:true` still requires the actual local human owner. Technical agent conclusions and legacy manual results are identified separately and never impersonate owner approval. Generic manual handoffs retain their result-entry path when the person is supplying an external result rather than accepting an existing delivery.

## Acceptance evidence

Exercise the installed ordinary project/global path in English and Simplified Chinese, including desktop/narrow layouts and keyboard input. Cover new/deleted files, stale/missing source and screenshots, project/attempt scope, real versus reported CI evidence, material preparation without parent advancement, account holds, concurrent/repeated requests, restart, Stop/late completion, stale decisions and receipt preservation. Verify new defaults and an older frozen manual gate without rewriting it. Separate model-free checks, provider execution, PR/CI and deployment evidence.
