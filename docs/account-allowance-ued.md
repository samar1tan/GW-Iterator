# Account allowance interaction

Read with the [module requirements](account-allowance-prd.md). Retain the existing [human workbench](human-workbench-ued.md) layout.

## Start and observe

The project workbench and saved-pipeline launch show one compact Codex allowance summary. The collapsed summary identifies the real returned window(s), remaining percentage and a concise readiness/trend statement. One disclosure contains reset time, observation age and the full comparison evidence. Keep the ordinary start action near the outcome; do not let allowance details dominate the workbench. Refresh is a read-only action. Do not add a quota form or a permanent new navigation module.

When no comparable history exists, say that the first bounded execution will provide a sample. A manual-only pipeline states that no Codex execution is needed. Unknown readings explain that availability cannot be confirmed; they must not look like an empty usage meter.

## Continue

The failed-stage inspector retains the concrete result and current recovery identity. The main recovery section shows account allowance plus the task's recent observed range, duration and sample count. The primary action uses the existing approved task/attempt boundary. At a real execution bound, describe one more attempt and its effect. At account exhaustion, show refresh and the actual reset time; do not offer an invented token refill.

If the account view cannot support an estimate or contradicts a previous approval, show that state directly and refresh the decision. A deliberate one-step owner continuation in an unavailable-data case must name its uncertainty and remain bounded. Unknown external execution is reconciled first.

## Evidence and attention

Task details distinguish account observations from executor token diagnostics. Show that other Codex sessions share the account; do not repeat this caveat in every row. Hide irrelevant model/token information for manual work. Activity records concise allowance decisions; raw provider events remain in technical history. Preserve selection and scroll while observations update.
