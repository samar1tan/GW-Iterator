# Governance in the existing workbench

These interactions implement the [knowledge context](knowledge-context-prd.md) and [template governance](template-governance-prd.md) requirements. Keep the five project destinations and current visual system. New ordinary launches have no configuration form.

## Start → prepared context → result

The request composer preserves its draft and exact start identity while model-free source preparation runs. The pending action names that operation. Closing a view does not mean cancellation or a failed submission. Missing required guidance opens a concrete Knowledge repair destination; no model task has started.

The execution inspector contains one Sources used disclosure beside its existing inputs/evidence. Its summary identifies relevant evidence and required guidance, not a quality percentage. Expanded rows show title, heading/location and a short reason such as task text, file identifier or check. Selecting a row opens the exact frozen excerpt, with neighboring passage navigation. Current source content is explicitly separate. Technical details retain hashes, algorithm versions and budget decisions.

No-match/limited coverage states explain the missing evidence and available search/read action. They do not show unrelated documents as recommended material. Required guidance failures distinguish missing content, unresolved conflict and capacity; repair reuses source edit/sync. Search and retrieval progress reflect real operations; timers are not relevance feedback.

## Knowledge review

Keep source/list/reader spatial roles. A source's ordinary editor offers Guidance or Reference with an explanation of what changes; weights and retrieval internals are not configuration fields. Guidance scope/section editing remains available.

Proposed lessons are a real filtered inbox in Knowledge. Each proposal shows source work, suggested reusable content and pending evidence. Retain/revise or decline uses the existing reader/form pattern. The global/project workbench may link an actual pending review, not an empty future-feature panel. Existing archive/restore remains in the same location.

A source/selection can receive relevance, outdated or conflict feedback with optional evidence/note. Record the distinction between retrieved and found useful; no obligatory rating interrupts delivery. Conflicting entries link to each other and keep their origin. Resolving a lifecycle problem is owner-controlled and cannot rewrite old work.

## Template library and project use

Projects provides Reusable templates beside existing project setup controls. The library separates role and pipeline templates and offers one concise purpose/applicability description. Opening a template shows its pinned revision, change summary and real origin. Retired templates stay readable; starting new installs from them is unavailable with an explanation.

From a project role/workflow, Save as template opens the maintained editor in template context. Portable content is editable; native bindings remain project owned. Model/effort defaults use the existing native English effort names. Creation does not silently rebind an existing project object.

An object's source row identifies its template version and project choices. View update opens a proposal-style preview with three useful groups: changes to apply, project choices to keep, conflicts or missing bindings. Show stage responsibility, checks, dependencies and return paths by name. Keep raw JSON under details. Normal no-conflict updates need only the final Apply action; real conflicts require a choice, not a second generic confirmation.

Apply names the exact target revision. During preparation it stays discoverable and prevents duplicate submission. A confirmed receipt survives refresh failure; recovery only reads the saved result. Changed project input invalidates the preview and retains the user's conflict choices for deliberate regeneration. Leaving the preview never applies it.

## Explain why work was selected

An execution's existing details show the actual workflow origin and selection method. A coordinator decision uses its recorded public reason. A human choice says it was chosen manually. A shortcut explains the actual ordering basis; do not call recent-use ordering task relevance. Keep the full frozen definition inspectable without repeating it in the main result.

## Cross-entry quality contract

Exercise new/saved requests, native/connected coordination, workers, project/global inspection and human/agent APIs. Preserve drafts, focus, keyboard behavior, return context and acknowledgement/observation boundaries. Inspect both locales and desktop/narrow layouts. A new source/template control must have a real owner, effect and recovery path before it is shown.

Performance work preserves current observations while reducing repeated decoding. Loading should remain actionable with several project views open. Hidden views suspend redundant observation; returning refreshes current state without replaying writes. Do not make stale account/Stop/receipt state look fresh to obtain a faster benchmark.
