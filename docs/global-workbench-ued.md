# Global workbench interaction

This document extends the top-level entry in UED. The existing project modules remain its focused workspaces.

## Spatial roles

The global header identifies GWI and the global level. A compact project list/filter provides scope; it does not open a project. The main area contains the request composer, attention items, current work and recent results. Every work row carries its project name, outcome and actual status. Optional project-entry links are explicit.

Opening a work row changes the global selection, with an explicit project-qualified URL, and shows the existing goal/execution surface inside the global shell. The global navigation and return action remain. On narrow screens the selected detail occupies the main area; returning restores the global filter and draft. Do not place a complete execution page inside a small modal or require a second browser tab.

## Request and detail

The request composer has one target project and the ordinary input. Use a useful existing selection when possible; otherwise ask for the target once through the visible selector. Never infer authority to change every project from an unscoped sentence. Retain drafts independently per target. No role, workflow, model or limit form is added.

A confirmed start opens its result in the global shell only if the operator has not moved to another selection while waiting. An acknowledged receipt remains reachable when the following read fails. The goal detail reuses in-place follow-up and clarification behavior. A child execution, selected stage, parent and previous/follow-up links remain in the global shell. Team/Knowledge/Settings links are explicit exits to the project workspace.

## State and feedback

Use labeled state icons, restrained counts and real current-step labels. A human decision row names the stage/question and opens the existing action form. Automatic refresh is observation, not evidence that a model is generating output. The detailed current-execution component retains its provider/activity, quiet and stale-state rules. Do not add perpetual decorative animation.

A quiet workspace shows the request and project list without competing empty cards. No projects retains the existing connect/manual-setup entry. Summary and detail errors have independent recovery and preserve the last readable record. Missing or mismatched project/work identities show a recovery action instead of silently selecting another item.

## Operational review

Walk start → global receipt → answer → follow-up, clarification → reply, and manual handoff → accepted result in isolated state. Switch project/filter/selection during slow observations and submissions. Check back/forward, refresh, keyboard and long names in English/Simplified Chinese at 1280px, 700px and 320px. Record actual observations and model-free fixture boundaries; do not claim a live provider run from controlled output.
