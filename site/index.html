CHOOSING A WORKFLOW

Codex directly or through GWI

Codex already supports goals, skills, review and subagents. It provides the reasoning and tools in both routes; GWI adds project-level workflow configuration, supervision and records.

WorkCodex directlyThrough GWI
Start and adaptCodex directlyDescribe a goal; let Codex plan, delegate and adapt in the conversation.Through GWIDescribe an outcome for the coordinator to choose existing workflows, or run a saved pipeline directly. Decisions and progress stay recorded.
SuperviseCodex directlyRead chat and agent activity, inspect changes, and steer the next action.Through GWIFollow named stages, owners, handoffs, artifacts and pending human decisions in one workbench.
Check and deliverCodex directlyAsk Codex for checks/review and follow your project's acceptance and publication process.Through GWIConfigured verification and human gates organize evidence, revision requests and delivery decisions.
Reuse and recoverCodex directlyReuse instructions and skills; resume or fork a conversation to continue work.Through GWIReuse versioned roles, pipelines and selected knowledge. Keep earlier attempts and check external progress before continuing failed work.

Use Codex directly for a focused fix or exploration with less setup. Choose GWI when repeatable work needs several handoffs or regular human review. GWI requires local GWI/Multica services and adds coordination/context overhead; faster or cheaper completion still needs measurement.

ON YOUR MACHINE

Run GW-Iterator locally

GWI connects a local web interface to Multica and your authenticated Codex installation. It does not require a hosted GWI account.

Node.js 24–26 · Git · curl · Docker Compose · Codex
GitHub operations also require an authenticated gh CLI.

Native execution is verified on macOS. Other hosts must pass the setup checks.
